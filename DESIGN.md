# Bulls and Cows — design notes

Обозначения: **L** — длина секрета (2–6), **B** — основание системы счисления (2, 8, 10, 16), **N** — число попыток в истории.

Вся логика лежит в `src/core/` и не знает про DOM. UI (`src/ui/`, `src/main.ts`) только вызывает функции ядра и рисует результат.

## Структуры данных

### Секрет и попытка — строка

`'0123'`, `'a1f0'`. Строка хранит ведущий ноль (у числа `0123` он бы потерялся), сама по себе неизменяемая и легко сравнивается посимвольно. Цифры hex всегда хранятся в нижнем регистре: секрет генерируется из алфавита `0123456789abcdef`, а попытка приводится к нижнему регистру в `normalizeGuess` (`src/core/game.ts`) перед записью в историю.

### Состояние игры — `GameState` (`src/core/types.ts`)

```ts
{
  settings: { length, base },
  secret: string,
  history: readonly HistoryEntry[],   // { guess, score: { bulls, cows } }
  status: 'playing' | 'won',
  startedAt: number,
  finishedAt: number | null,
}
```

- Все поля `readonly`, поэтому мутацию поймает компилятор.
- `history` — массив, потому что важен порядок попыток, а число попыток — это просто `history.length` (`getAttempts`).
- Новая попытка добавляется только через `[...state.history, entry]` в `submitGuess`. Старые записи переходят в новый массив теми же объектами, их никто не трогает (это проверяет тест `keeps old entries untouched`).
- Если попытка невалидная, повторная или игра уже выиграна, `submitGuess` возвращает **тот же объект** состояния. Поэтому задвоения в истории быть не может.
- Время не берётся внутри ядра: `startedAt` и `now` передаются параметрами, так же как `random` в `generateSecret`. Благодаря этому все функции чистые, а тесты детерминированы.

### Рекорды — плоский массив `RecordEntry[]` (`src/core/records.ts`)

```ts
{
  (length, base, attempts, timeMs, date);
}
```

Каждая запись хранит свои настройки, а таблица показывается отдельно для каждой комбинации length/base (`getRecordsFor`). Топ-10 считается внутри своей комбинации (`addRecord`), записи других комбинаций не трогаются. Массив сохраняется в `localStorage` как JSON, при чтении `parseRecords` отбрасывает битые данные.

### Вспомогательные структуры

- `Set` — в `evaluateGuess` (быстрая проверка «есть ли цифра в секрете») и в `hasUniqueDigits` (поиск повторов).
- `Map` — кэш внутри `memoize`.
- `AppState` в `src/main.ts` — `{ settings, game, records, message }`, обновляется через `setState` новым объектом.

## Алгоритмы

### `evaluateGuess(secret, guess)` — `src/core/evaluate.ts`

1. Обе строки разбиваются на символы и приводятся к нижнему регистру: `[...value].map(normalizeDigit)`.
2. Цифры секрета кладутся в `Set`.
3. Один `reduce` по цифрам попытки с начальным значением `{ bulls: 0, cows: 0 }`:
   - цифра совпадает с цифрой секрета на той же позиции → `bulls + 1`;
   - иначе, если цифра есть в `Set` секрета → `cows + 1`;
   - иначе счёт не меняется.

На каждом шаге создаётся новый объект счёта, ручных циклов и изменяемых счётчиков нет. Цифры уникальны, поэтому каждая цифра попытки попадает ровно в одну категорию и двойного счёта не бывает.

### `countPossibleSecrets(length, base)` — `src/core/combinatorics.ts`

Число размещений без повторений P(B, L) = B! / (B − L)!. Первую позицию можно заполнить B способами, а дальше задача сводится к той же самой, но на одну позицию короче и с одной цифрой меньше:

```
P(B, 0) = 1
P(B, L) = 0                    если L > B
P(B, L) = B · P(B − 1, L − 1)
```

Ограничения на ведущий ноль нет, поэтому ничего не вычитается. Функция обёрнута в `memoize` (`src/core/memoize.ts`) — это HOF, которая хранит результаты в `Map` по ключу `JSON.stringify(args)`. Рекурсивный вызов идёт через уже мемоизированную функцию, поэтому в кэш попадают и промежуточные значения: после `P(16, 6)` значение `P(15, 5)` тоже уже посчитано.

### `generateSecret(length, base, random)` — `src/core/secret.ts`

Рекурсивная `pickDigits(available, count, random)`: берёт цифру по индексу `floor(random() * available.length)`, убирает её из строки доступных цифр и вызывает себя для оставшихся. Цифра, которую уже взяли, выпасть повторно не может, поэтому уникальность получается без проверок и перегенераций. `random` передаётся параметром (по умолчанию `Math.random`), и в тестах подставляются детерминированные источники.

## Сложность

| Функция                | Время                                     | Почему                                                                                                                                                                                                                           |
| ---------------------- | ----------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `generateSecret`       | **O(L · B)**                              | L рекурсивных шагов, на каждом `removeAt` копирует строку доступных цифр длиной ≤ B. Глубина рекурсии L, память O(L · B) на промежуточные строки. При B ≤ 16 и L ≤ 6 это по сути константа.                                      |
| `evaluateGuess`        | **O(L)**                                  | Разбор строк — O(L), построение `Set` — O(L), `reduce` — L шагов, в каждом сравнение по индексу и `Set.has` за O(1), новый объект из двух полей — O(1).                                                                          |
| `isValidGuess`         | **O(L · B)**                              | Проверка длины O(1), `every` по L символам, каждый проверяется `alphabet.includes` по строке длиной B. `hasUniqueDigits` через `Set` — O(L). Если бы алфавит был `Set`, было бы O(L), но при B ≤ 16 строка проще и не медленнее. |
| `countPossibleSecrets` | **O(L)** первый вызов, **O(1)** повторный | Рекурсия глубиной L, на каждом шаге одно умножение и обращение к `Map`. Повторный вызов с теми же аргументами — одно чтение из кэша.                                                                                             |

Для полноты: `submitGuess` — O(L · B + N): валидация, поиск повтора через `some` по истории и копирование массива истории.

## Принципы чистого кода

- **Одна ответственность.** Каждый файл ядра отвечает за одно: `digits.ts` — алфавит и валидатор цифр, `validation.ts` — проверка попытки, `evaluate.ts` — подсчёт быков и коров, `secret.ts` — генерация, `combinatorics.ts` — подсчёт вариантов, `game.ts` — состояние раунда, `records.ts` — рекорды. В UI каждый экран — своя функция: `settingsView`, `gameView`, `recordsView`.
- **Маленькие функции с понятными именами.** `secret.ts` разбит на `pickIndex`, `removeAt`, `pickDigits`. В `game.ts` — `normalizeGuess`, `wasGuessed`. Предикаты названы как вопросы: `isValidGuess`, `isLengthAvailable`, `hasUniqueDigits`, `isSameSettings`.
- **DRY.**
  - `normalizeDigit` (`digits.ts`) — единственное место, где решается вопрос регистра. Используется в валидаторе, `hasUniqueDigits`, `evaluateGuess`, `normalizeGuess`.
  - `createDigitValidator` используется и в `isValidGuess`, и в фильтре ввода (`guessInput` в `src/ui/game-view.ts`).
  - Каррированный `isSameSettings` используется и в `getRecordsFor`, и в `addRecord`.
- **Без магических чисел и строк.** `ALL_DIGITS` (`digits.ts`), `BASES` и `LENGTHS` (`settings.ts`), `RECORDS_LIMIT` (`main.ts`), `KEY` (`storage.ts`), `EMPTY_SCORE` (`evaluate.ts`).
- **Ранний выход вместо вложенных условий.** `getGuessError` и `submitGuess` (`game.ts`), `pickDigits` (`secret.ts`), `createRecord` и `parseRecords` (`records.ts`).
- **Ошибки как значения.** `getGuessError` возвращает `'invalid' | 'duplicate' | 'finished' | null`, а не бросает исключение. Тексты сообщений лежат отдельно в `errorMessages` (`main.ts`), и логика о них не знает.
- **Зависимости передаются явно.** `random` в `generateSecret`, `now` в `submitGuess` и `getElapsedMs`. Побочные эффекты (`Date.now`, `Math.random`, `localStorage`, DOM) собраны в `src/main.ts` и `src/ui/`.
- **Типы как документация.** `Base = 2 | 8 | 10 | 16`, `GameStatus`, `GuessError`, `readonly` во всех структурах (`types.ts`).
- **Правила, которые проверяет линтер.** В `eslint.config.js` для `src/core/**` запрещены `class` и `this`, плюс `prefer-const`, `eqeqeq`, `no-param-reassign`.
